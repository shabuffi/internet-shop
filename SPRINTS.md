## Спринт 13 — «Application error» на витрине: исчерпание пула соединений БД · 2026-07-14/15

**Проблема:** на сайте (особенно с телефона) вместо страниц — «Application error: a server-side
exception… Digest: 3755971422». Возникала волнами, привязанными к обходам поисковых ботов.

**Корневая причина (доказана логами прода, read-only):** пул соединений БД (`5 + 10 overflow = 15`
на воркер) недоразмерен относительно конкурентности, которую приложение себе разрешает (threadpool
FastAPI `40` тредов × 2 воркера). Любой всплеск параллельных запросов к БД устойчиво выше 15
исчерпывает пул → `sqlalchemy.exc.TimeoutError: QueuePool limit … reached` → фронт по своему
таймауту 8с отдаёт «Application error». Два независимых **триггера** одного корня:
1. **Веерная раздача картинок** (HTTP/2, живые посетители): `get_product_image` держал соединение
   всё время чтения файла с диска.
2. **`/sitemap.xml` на `force-dynamic`** (доминировал ночью): несколько SEO-краулеров тянут карту
   внахлёст, каждый = полный SSR-рендер 261 запрос `list_products` → десятки параллельных цепочек.

**Исключено (проверено):** обмен МойСклад (0 всплесков в его окнах), нехватка ресурсов/OOM/рестарты,
мобильный рендер, N+1, утечка сессий, «медленный SQL» (`list_products` в покое 0.8мс).

**Исправлено — Этап 1 (коммит `6fc2f91`, задеплоено 14.07):**
- `products.py get_product_image`: берём только имена файлов (`Row`, не ORM-сущность →
  `DetachedInstanceError` невозможен конструктивно) и `db.close()` **до** чтения файла.
- `db/session.py`: `pool_timeout` 30→5с (фронт всё равно уходит на 8-й секунде).
- Замер до/после (локально): соединения, удерживаемые вхолостую, 15/15 → 3-6; ожидание при
  исчерпанном пуле 30.0с → 5.0с. Пост-деплой: 0 падений `/image`.

**Исправлено — Этап 2 / P0 (коммит `4ab2167`, задеплоено 15.07):**
- `sitemap.ts`: `force-dynamic` → **ISR `revalidate=3600`** + `page_size=100`. Next кэширует карту
  и ревалидирует single-flight (несколько ботов внахлёст = один рендер, остальные — из кэша).
- `Dockerfile.prod`: `ARG/ENV SITE_URL` перед `npm run build` (ISR пре-рендерит sitemap на билде —
  без домена в env ссылки уехали бы на `http://localhost`).
- `docker-compose.prod.yml`: `frontend.build.args: SITE_URL`.
- **Подтверждение (наблюдение 10ч+, read-only):** 12714 запросов, **0 QueuePool / 0 Application-error /
  0 5xx / 0 EOF-с-открытой-транзакцией**. ISR: 548 обходов sitemap → лишь 30 прогревов (94% из кэша).
  Пул под пиком 115 req/мин (обход карточек) — 0 исчерпаний. До фикса ночь = 3381 QueuePool.

**Отложено в backlog (архитектурные улучшения, НЕ срочные — оба триггера закрыты):**
- **P1** — согласовать пул с конкурентностью (`pool_size`/`max_overflow` вверх ЛИБО ограничить
  threadpool до размера пула). Чинит корень; сейчас профилактика, а не активная проблема.
- **P2** — `proxy_cache` картинок в nginx, но **сначала** версионирование URL (`?v=`) / ETag от
  содержимого (иначе замена фото в МойСклад не доедет до пользователей).
- **P3** — `exchange_get/exchange_post`: убрать `async def` + sync-БД (блокируют event loop на 4-6с
  каждый обмен). Sentry на фронт (сейчас его нет — половина расследования ушла на археологию логов).

**Файлы:** `products.py`, `db/session.py`, `sitemap.ts`, `Dockerfile.prod`, `docker-compose.prod.yml`.
`robots.ts` НЕ трогали (тот же `force-dynamic`-костыль, но 1 fetch — не в проблеме; отложено с P1-P3).

## Спринт 12 — Обратная синхра состава заказов, витрина (Новинки/Спецпредложения), мобильная админка · 2026-07-07

**Обратная синхронизация заказов из МойСклад (ЗАДЕПЛОЕНО):**
- `commerceml_order_status.py`: парсер `orders.xml` теперь тянет и **состав** (Товары: Ид/Артикул/
  Наименование/ЦенаЗаЕдиницу/Количество), и **итог** (`<Сумма>` уровня документа).
- `exchange.py _apply_order_statuses`: перезаписывает `total_amount` и позиции заказа снимком из
  МойСклад (product_id по moysklad_id; остаток не трогаем; без лишних перезаписей). Метка
  `exchange:last_orders_sync`. Тесты в `test_order_status.py`. ⚠️ прошлые изменения (сделанные до
  выката) МойСклад повторно не шлёт — ORD-0013 обновили разовым применением сохранённого orders.xml.

**Админка:**
- Заказы: в списке виден **состав** (раскрывашка), позиция = «кол-во × цена = сумма», имена
  чистятся от префиксов (с4/ЧЗ) через `cleanProductName`.
- Товары: наличие показываем **числом только при stock>0** (иначе «Нет»/«Скрыт»); фильтр
  наличия = `available AND stock>0`; фильтры в нашем стиле (белые, своя стрелка), на мобиле 2×2.
- Обзор: блок «Синхронизация с МойСклад» (каталог/заказы/последний контакт); карточки компактные,
  3 в ряд на мобиле.
- **Мобильная админка**: меню — горизонтальной лентой сверху (шапка магазина оставлена); «Политика»
  в одну колонку; убрана кнопка «Обновить» на «Синхронизации».
- **HelpHint** `?` у заголовков разделов (наведение на ПК / клик на телефоне); видимые описания
  перенесены в подсказки (Покупатели/Настройки/Баннеры/Политика).

**Витрина:**
- Плитка каталога: степпер 0/+ **прямо в корзину** (без кнопки «В корзину»); **минимальное
  количество** (доп. поле МойСклад «Минимальная единица отгрузки» → показ «Минимальное количество
  для заказа») кладётся **партиями** (шаг/минимум N, подпись «кратно N шт.»).
- **Новинки / Спецпредложения**: секции-ряды на главной (выше «Популярных разделов») + отдельные
  страницы `/novinki`, `/special` с тулбаром (сортировка, «С фото», плитки/строчки) через общий
  `PromoListing`; пункты в меню; бейджи NEW (синий) / % (красный). Спецпредложения — из категории
  **«РАСПРОДАЖА»** (поиск по имени); Новинки — пока заглушка (по алфавиту), ждут поле в МойСклад.
- Cookie-баннер (152-ФЗ); поле «Координаты склада» → чистая метка на карте; сворачиваемый состав
  заказа в ЛК; блоки-преимущества компактнее; фикс липкой корзины снизу (на всю ширину с отступами);
  неприметная ссылка «Вход для сотрудников» в подвале.

**Осталось/планы:** поля «Новинка»/«Спецпредложение» в МойСклад (тогда сменим источник секций и
меню-фильтры); корп. почта для «Забыли пароль?»/писем; next/image, Sentry, Яндекс.Метрика.

## Спринт 1 — Прод перестал виснуть по ночам · 2026-06-21

**Проблема:** каждую ночь фронтенд (Next.js) уходил в `unhealthy`, nginx отдавал 504. Прод —
Ubuntu-сервер `139.100.226.168`, `/opt/internet-shop`, деплой через `git pull && ./deploy.sh`.

**Причина:** серверные `fetch` к backend без таймаута (корневой `layout.tsx` рендерится на КАЖДЫЙ
запрос; ночной обмен МойСклад тормозит backend; под трафиком ботов подвисшие SSR-запросы
накапливаются и вешают Next.js). Docker сам НЕ перезапускает `unhealthy`-контейнер.

**Готово (коммит `0c85990`, задеплоено):**
- `frontend/src/app/layout.tsx` и `frontend/src/lib/api.ts`: `AbortSignal.timeout(8000)` на все
  серверные fetch.
- `docker-compose.prod.yml`: сервис `autoheal` (willfarrell/autoheal) — перезапускает зависший
  контейнер за ~30с. Проверено: после деплоя 8 контейнеров, frontend healthy.
