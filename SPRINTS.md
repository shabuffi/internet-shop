## Спринт 8 — Инцидент с фото + старт «Личного кабинета» · 2026-06-29

**Инцидент (РАЗРЕШЁН):** фикс `bd3379e` (снял guard `if parsed_product.images`) при обмене
**обнулил ссылки на фото у всех товаров** — у этого аккаунта обычный `import.xml` идёт без
`<Картинка>`. Файлы картинок на диске уцелели (`media_data`, 354 файла). Восстановил ссылки из
бэкапа `/root/backup_2026-06-18_1300.sql` (55 товаров) — фото вернулись на витрину. В коде —
«умный» фикс: чистим/обновляем фото только в раунде, который реально несёт картинки
(`round_has_images = any(p.images for p in catalog.products)`); внутри такого раунда пустой список
по-прежнему удаляет снятые фото. **На проде стоит ручной хотфикс (простой guard); origin =
умный фикс. Прод НЕ обновлён до origin — деплой отдельным шагом (см. ниже).**

**Готово (в git, origin/main):**
- `65d1a07` fix(sync): `round_has_images` — фото не затираются вне фото-раунда.
- `9ae548b` **Этап 1**: наценка +10% для гостей считается на бэке (`services/pricing.adjusted_price`,
  `DEFAULT_MARKUP_PERCENT`), применена в списке/карточке и в расчёте заказа (в МойСклад — фактическая цена).
- `8f133c0` **Этап 2 (бэк)**: модель `User`, миграция `e7f8a9b0c1d2`, схемы с валидацией (ИНН 10/12
  для ООО/ИП, согласие обязательно), эндпоинты `/api/v1/auth/register|login|logout|me`
  (bcrypt + JWT в httpOnly-куке `customer_token`, без подтверждения email).
- `92157b2` **Этап 2 (фронт)**: страницы `/register`, `/login`, `/account`, `lib/authApi.ts`,
  ссылка «Войти/Кабинет» в шапке (`AccountNav`). tsc чистый.
- **Этап 3**: страница `/offer` — шаблон политики обработки ПД (152-ФЗ) для согласия при регистрации.

**Решения по ТЗ:** в МойСклад уходит фактическая цена; регистрация без подтверждения email;
текст оферты — шаблон-рыба (вычитка заказчиком). План этапов — `PLAN-личный-кабинет.md`.

**Осталось (этапы 4-6):** персональные цены для вошедших; админка «Пользователи + скидки»;
чекаут (доставка самовывоз/ТД/ТК + передача данных и доставки в МойСклад).

**⚠️ Деплой на прод (когда решим):** прод сейчас на безопасном ручном хотфиксе, рабочее дерево
`/opt/internet-shop` имеет незакоммиченную правку `import_service.py`. Чтобы выкатить origin:

## Спринт 7 — Синхронизация каталога/фото, перекраска лого, favicon · 2026-06-29

**Контекст (замечания заказчика):** (1) правки товара/фото в МойСклад не доезжают до сайта —
заменённые фото обновляются, а удалённые висят; (2) перекрасить лого под цвет сайта (прислан
эталон `ИНЖЕНЕР/лого-другой-цвет.jpg`) и поставить новый favicon (папка `favicon/`); (3) что за
правка висела в `LeadForm.tsx`.

**Готово (локально, ждёт деплоя):**
- **Удалённые фото теперь чистятся** (`backend/app/services/import_service.py`): guard был
  `if parsed_product.images and not images_manual` → при удалении ВСЕХ картинок в МойСклад
  приходил пустой список и старые фото не затирались. Список картинок из import.xml —
  авторитетный (картинки описываются в `<Товар>`, не в offers.xml), поэтому guard ослаблен до
  `if not images_manual` — пустой список = удалили = чистим. Цена/остаток не затронуты (их
  защищает отдельный `has_offer`, они живут в offers.xml). ⚠️ Проверить на первом реальном
  обмене, что МойСклад не шлёт import.xml без `<Картинка>` для товаров, у которых фото есть.
- **Заменённые фото больше не «залипают» в браузере** (`backend/app/api/v1/endpoints/products.py`,
  эндпоинт `/{id}/image`): было `Cache-Control: max-age=86400` без ревалидации → новое фото не
  показывалось до суток. Стало `max-age=600, stale-while-revalidate=86400` + **ETag по имени
  файла** (при замене фото имя файла в МойСклад меняется → ETag другой → браузер тянет новое;
  тот же ETag → 304 без перекачки). Свежесть на витрине — в пределах ~10 мин. (В админке уже
  был свой `?v=` для мгновенности — её не трогали.)
- **Про «правки текста не доезжают»:** имя всегда перезаписывается; описание/артикул/код/
  характеристики — только если пришли непустыми (чтобы пустое не затирало). Витрина кэширует
  ответ API 60 c (`lib/api.ts` `revalidate:60`) → правки видны после ближайшего обмена МойСклад
  + до 60 c. Это ожидаемо, не баг.
- **Лого перекрашено под сайт** (`frontend/public/logo.svg`): синий `#016AFF → #003399`
  (`--accent`), красный `#E31E24 → #E02424` (`--accent-2`). Цвета сэмплированы из присланного
  эталона — совпали с переменными темы. `logo-white.svg` (футер) не трогали — он белый.
- **Новый favicon** (`favicon/` → `frontend/public/`): `favicon.ico/.svg`, `favicon-96x96.png`,
  `apple-touch-icon.png`, `web-app-manifest-192/512`, `site.webmanifest` (имя «ТД ИНЖЕНЕР»,
  theme `#003399`). `layout.tsx` `generateMetadata`: блок `icons` теперь указывает на статичный
  набор + `manifest`; убран показ favicon из загруженного в админке лого (`/api/v1/admin/logo`).
- **Пункт 3 — `LeadForm.tsx`:** это была готовая правка текста (убрали «прайс и −10%» →
  «Уточнить условия поставки / условия оптовой поставки»). Логику не меняли. Закоммитить вместе.

**Тронутые файлы:** `backend/app/services/import_service.py`,
`backend/app/api/v1/endpoints/products.py`, `frontend/public/logo.svg`,
`frontend/public/site.webmanifest` (+favicon-файлы), `frontend/src/app/layout.tsx`,
`frontend/src/components/LeadForm.tsx` (правка из прошлой сессии).

**Отложено / на проверке:** убедиться вживую, что удалённые фото уходят после обмена;
при желании — мгновенное обновление фото на витрине через `?v=updated_at` (как в админке).

## Спринт 3 — Карта зоны доставки на главной · 2026-06-21

**Контекст:** ТЗ — «вместо пустого синего пространства справа в баннере разместить карту России
с регионами доставки». Регионов по факту **6** (не 8): Тверская, Московская, Смоленская,
Новгородская, Владимирская, Ярославская.

**Готово (локально, ждёт деплоя):**
- `frontend/src/components/DeliveryMap.tsx` — НАСТОЯЩАЯ карта 6 областей с точными границами.
  Контуры построены из OSM-GeoJSON (репозиторий timurkanaz/Russia_geojson_OSM): районы каждой
  области объединены (shapely unary_union), спроецированы (коррекция долготы по cos(ср.широты)),
  упрощены (simplify 0.01°), переведены в SVG-пути (viewBox 920×748). Москва-город влит в
  Московскую область (иначе МО — «подкова» с дыркой и выглядела маленькой). Дырки залиты;
  под областями подложка-union, закрывающая тонкие щели между независимо упрощёнными
  границами. Ховер-подсветка на CSS, без клиентского JS.
- `frontend/src/app/page.tsx` — hero перестроен в 2 колонки (текст слева, карта справа, скрыта на
  мобильных через `hide-mobile`); список регионов в блоке «Доставка» расширен до 6.

**Как пересобрать карту (если поменяется список регионов):** скачать нужные GeoJSON из
timurkanaz/Russia_geojson_OSM (папки Regions/CFO, SZFO), прогнать через shapely (union→project→
simplify) и сгенерировать пути. shapely ставился разово ЛОКАЛЬНО для генерации — в зависимости
проекта НЕ входит; в рантайме карта это статический SVG.

## Спринт 1 — Прод перестал виснуть по ночам · 2026-06-21

**Проблема:** каждую ночь фронтенд (Next.js) уходил в `unhealthy`, nginx отдавал 504. Прод —
Ubuntu-сервер `139.100.226.168`, `/opt/internet-shop`, деплой через `git pull && ./deploy.sh`.

**Причина:** серверные `fetch` к backend без таймаута (корневой `layout.tsx` рендерится на КАЖДЫЙ
запрос; ночной обмен МойСклад тормозит backend; под трафиком ботов подвисшие SSR-запросы
накапливаются и вешают Next.js). Docker сам НЕ перезапускает `unhealthy`-контейнер.

**Готово (коммит `0c85990`, задеплоено):**
- `frontend/src/app/layout.tsx` и `frontend/src/lib/api.ts`: `AbortSignal.timeout(8000)` на все
  серверные fetch.
- `docker-compose.prod.yml`: сервис `autoheal` (willfarrell/autoheal) — перезапускает зависший
  контейнер за ~30с. Проверено: после деплоя 8 контейнеров, frontend healthy.
