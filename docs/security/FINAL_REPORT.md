# Итоговый отчёт по аудиту безопасности

Дата: **2026-07-14**. Проект: **internet-shop** (`td-engineer.ru`). Статус: аудит и исправления Stages 1–3 завершены и **задеплоены на прод** (commit `9947863`, alembic head `d6e7f8a9b0c1`), пост-деплой проверки зелёные.

## 1. Краткое описание проекта

Production-магазин с МойСклад как мастер-каталогом. Backend — FastAPI (Python 3.12), фронт — Next.js 15 (SSR), БД — PostgreSQL 16, брокер — Redis 7, фоновые задачи — Celery. Интеграция с МойСклад **только через CommerceML** (обмен XML: каталог/остатки/картинки вниз, заказы вверх), пароль аккаунта МойСклад не используется. Всё в Docker за nginx-реверс-прокси; прод на HTTPS (Let's Encrypt).

## 2. Что проверялось

- **Backend** — авторизация, обмен CommerceML, заказы, заявки, админка, dev-страница, работа с файлами, сериализация, SQL.
- **Frontend** — XSS/DOM-XSS, `dangerouslySetInnerHTML`, хранение токенов, CSP-поверхность.
- **API** — аутентификация, JWT, cookies, CORS, rate-limiting, обработка ошибок, утечки данных, загрузка файлов.
- **Docker** — compose (dev/prod), Dockerfile, привилегии, `docker.sock`, секреты в образах.
- **Конфигурация** — `.env`/`.env.prod(.example)`, nginx (TLS/заголовки), секреты.
- **Миграции** — Alembic: корректность, downgrade, конфликты, цепочка ревизий.
- **Документация** — согласованность `docs/security/`.

## 4. Что было исправлено

**Stage 1 (код):**
- H-1: обмен CommerceML переведён на fail-closed (без кред — доступ закрыт).
- H-2: `/docs`, `/redoc`, `/openapi.json` доступны только при `DEBUG`.
- H-3: security-заголовки в `nginx.prod.conf` (HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy).
- M-2: rate-limit на `/orders` и `/leads` (существующий механизм).
- M-5: `/admin/setup` под одноразовым `SETUP_TOKEN` + `hmac.compare_digest` (не через DEBUG).

**Stage 3 (код + миграции):**
- B-1: номер заказа через PostgreSQL SEQUENCE `order_number_seq` (миграция `d5e6f7a8b9c0`); dialect-aware фолбэк `MAX+1` для тестового SQLite.
- B-2: unique-индекс `ix_users_phone` (миграция `d6e7f8a9b0c1`) с гардом на дубли (не удаляет данные).

**Финальный review:** устранены 3 регрессии в собственных изменениях (nextval на SQLite, тесты обмена под старый soft-mode, исчерпание rate-limit в тестах). **162 теста зелёные.** Миграции: единый линейный head, downgrade/upgrade проходят.

Технические детали — в `FIXES.md`, мотивация решений — в `DECISIONS.md`.

## 6. Что не подтвердилось

Проверены и признаны **отсутствующими / неэксплуатируемыми** в этом проекте:

- **XSS / DOM XSS** — единственный `dangerouslySetInnerHTML` (цвет темы) валидируется regex hex; контент политик рендерится React-элементами (авто-экранирование); токены в httpOnly-куках.
- **SQL Injection** — только SQLAlchemy ORM/`select()`; пользовательский ввод в поиске идёт bind-параметром + `re.escape`; сырых SQL-строк нет.
- **IDOR** — история заказов строго по `user_id`; все `/admin/*` под auth.
- **SSRF** — исходящие только на фиксированные `api.vk.com`/SMTP; URL из ввода сервер не запрашивает.
- **Command Injection** — нет `os.system`/`subprocess`/`eval`/`exec`.
- **Path Traversal / LFI / Zip-Slip** — имена файлов сводятся к `basename`.
- **Email Header Injection** — адреса валидируются (без CR/LF), пользовательский текст только в теле письма.
- **CSRF** — cookies `SameSite=Lax` + CORS-список без wildcard.
- **Mass Assignment** — `body: dict`-эндпоинты whitelist-ят ключи; цену/`user_id` из запроса не берут.
- **Open Redirect / Response Splitting / Request Smuggling / Prototype Pollution / ReDoS** — векторов не найдено.
- **XXE / entity-DoS** — libxml2 блокирует и внешние сущности, и amplification (проверено тестом) → только hardening-рекомендация.
- **Host-header reset poisoning** — ссылка сброса строится из `ALLOWED_ORIGINS`, не из `Host`.
- **Секреты в истории Git / в Docker-образах** — не найдено (`.env` в git не коммитился; прод-образ секретов не содержит).

## 7. Общая оценка безопасности

Честная техническая оценка: **база кода — крепкая**; основные классы веб-уязвимостей закрыты или отсутствуют. Ключевые риски были не в коде, а в **конфигурационных дефолтах** (fail-open, открытый Swagger, отсутствие заголовков) — они устранены. Наибольший остаточный риск сместился в **операционную плоскость** (секреты в `.env`, непроверенный прод-конфиг, `docker.sock`, неаудированный хост).

| Компонент | Оценка | Комментарий |
|-----------|--------|-------------|
| Backend | 🟢 Хорошо | ORM, bcrypt, корректный JWT, валидация ввода; инъекций нет. |
| Frontend | 🟢 Хорошо | Токены в httpOnly, XSS-поверхность закрыта, экранирование React. |
| API | 🟢 Хорошо (после фиксов) | Auth/JWT/CORS корректны; rate-limit добавлен; Swagger закрыт на проде. |
| Database | 🟢 Хорошо | Не-root доступ, наружу не публикуется (prod), race-free номера, уникальный телефон. |
| Docker | 🟡 Удовлетворительно | Контейнеры под non-root; остаётся `docker.sock` в autoheal (M-1). |
| Production Config | 🟡 Требует проверки | `.env.prod` не проверен (COOKIE_SECURE/DEBUG/SECRET_KEY); секрет в `.env` ждёт ротации. |
| Documentation | 🟢 Хорошо | `docs/security/` актуальна и согласована (5 документов). |

Итог: после деплоя Stage 1+3 и закрытия операционных пунктов раздела 5 — состояние **хорошее** для публичного релиза.

## 8. Рекомендации перед деплоем

Выполнить вручную до/во время выкладки на production:

1. **Секреты (`.env`):** сменить `MOYSKLAD_PASSWORD` в Google/МойСклад; удалить мёртвый блок `MOYSKLAD_*`/`SYNC_INTERVAL_SECONDS`.
2. **`.env.prod` на сервере:** убедиться, что `COOKIE_SECURE=true`, `DEBUG=false`, `ALLOWED_ORIGINS=["https://td-engineer.ru"]`, `SECRET_KEY` — сильный и не из примера.
3. **B-2 (телефоны):** перед миграцией выполнить `SELECT phone, COUNT(*) FROM users GROUP BY phone HAVING COUNT(*)>1;` — при наличии дублей устранить вручную (миграция намеренно упадёт, данные не удаляет).
4. **Деплой:** `git pull && ./deploy.sh` (авто-бэкап БД перед миграциями). Проверить, что применились обе миграции (`alembic current` = `d6e7f8a9b0c1`).
5. **SETUP_TOKEN:** если понадобится первичная установка админа — задать `SETUP_TOKEN` временно и убрать после.
6. **Дым-тест после деплоя:** витрина/каталог 200; `/docs` → 404; обмен МойСклад проходит (креды заданы); заказ оформляется; в ответах присутствуют security-заголовки.
7. **Инфраструктура (по возможности):** аудит прод-хоста по SSH; запинить `autoheal` по digest (M-1).
