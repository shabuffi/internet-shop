# Security Changelog — internet-shop

Хронология изменений по безопасности. Новые записи — сверху.

## 2026-11-01 — Видимый знак на сайте: небольшой значок в правом нижнем углу (решение владельца)
- Владелец всё же хочет знак на фото на сайте (чтобы оставался на скриншоте): «небольшой, в правом нижнем углу». По предложению разработчика — иконка вкладки (шестерёнка с домиком на белом круге, `app/assets/watermark-icon.png`), а не полный логотип: компактна и читается на любом фоне.
- `MEDIA_WATERMARK_MARK=icon|logo` (по умолчанию icon), `MEDIA_WATERMARK_OPACITY` по умолчанию 0.85; значок ~12% ширины. Копии «для сохранения» — по-прежнему пять полных логотипов.
- Встроенные картинки разделов (старый режим): видимые версии со значком в `public/categories/wm/` (`make_static_save_copies.py --visible`).
- Проверка: 338 тестов (+4); в браузере — карточка товара и плитки разделов со значком.

## 2026-11-01 — Шаг 1 деплоя (флаги выключены) безопасен для витрины
- Найдено при оценке «поломает ли прод»: при `MEDIA_VARIANTS=false` слои «для сохранения» получали бы ОРИГИНАЛ — каждая карточка тянула бы его дважды (×2 трафик), а слой отдавал бы чистое фото. Теперь `size=save|thumb_save` (и `?size=save` картинки категории) при выключенных копиях → 404.
- Компонент `SaveLayer`: слой ловит клики только после реальной загрузки копии (проверка и на монтировании — SSR), иначе `pointer-events: none` и правый клик попадает в видимое фото. Раньше несработавший слой оставался сверху «битой» прозрачной картинкой.
- `nginx.prod.conf` проверен `nginx -t` локально (подставные сертификаты) — ок.
- Проверка: 334 теста (+3); локально в режиме «флаги выключены» — слои 404, сверху видимое фото; после включения — всё как раньше.

## 2026-11-01 — Слой «для сохранения» на всех превью товаров
- Владелец заметил: в «Новинках» и др. превью скачиваются без логотипов. Слой был только на большом фото карточки и на плитках категорий. Теперь он на всех превью: карточки `PromoCard` (главная, «Новинки», «Спецпредложения», «Убойные цены», промо), сетка каталога, мини-превью режима «Список», корзина, оформление, миниатюры галереи.
- Новая копия `thumb_save` (500px, логотипы `MEDIA_WATERMARK_SAVE`) — чтобы каждая карточка не тянула ещё и 1200px.
- Проверка: 331 тест (+1); в браузере на каждом типе страницы слой — верхний элемент над каждым превью с фото, клики/переключение галереи работают.

## 2026-11-01 — Картинки категорий под той же защитой + запрет GIF/SVG для фото
- **Картинки категорий** (плитки «Популярные разделы»): загруженные в админке иконки — `/admin/media/{name}?size=card` для плитки (900px, без знака), прямой адрес без параметра и `size=save` — копия с логотипами; поверх плитки невидимый слой (`CategoryImage protect`). Встроенные картинки старого режима (`public/categories/*.jpg`) — заранее сделанные копии с логотипами в `public/categories/save/` (`backend/scripts/make_static_save_copies.py`) и тот же слой. Защищены оба режима: какой включён на проде, не проверялось (с продом не работаем).
- **GIF/SVG запрещены** для фото товара (загрузка и привязка бесхозного файла) и для иконки категории: они не обрабатываются и уходили бы как есть; SVG с публичного адреса своего домена — потенциальный XSS. Логотипы брендов/баннеры не затронуты.
- Проверка: 330 тестов (+6); в браузере оба режима плиток (ПК + телефон): слой — верхний элемент, клик ведёт в категорию.

## 2026-11-01 — Фото с телефона (48–50 Мпикс), загруженные в админке, больше не уходят оригиналом
- Найдено при разборе вопроса «а если фото загружено не через МойСклад»: защита памяти (`_MAX_PIXELS` 25 Мпикс) отказывала таким файлам, и наружу уходил **оригинал** — полный размер, EXIF с GPS, без логотипа. На текущих прод-фото не проявлялось (максимум 4032px ≈ 12 Мпикс).
- Фикс: JPEG декодируется сразу уменьшенным (`draft`) ДО проверки лимита. Реальный кадр 8064×6048: все копии за 0.12 с, повёрнуты, без EXIF. PNG/WebP за лимитом — по-прежнему оригинал (draft для них нет; редкость).
- Путь «загрузка в админке → витрина → сохранение» покрыт сквозным тестом. Итог 324 теста.

## 2026-11-01 — Видимое фото на карточке уменьшено до 900px
- Раз видимая копия без знака, чем она мельче, тем меньше ценность чистого фото по прямому адресу/скриншоту. `card` 1200 → 900px (рамка фото ~365px ПК / ~343px телефон — 900 хватает и для Retina; проверено в браузере: dpr 2 → нужно 730px). Копия «для сохранения» с логотипами остаётся 1200px; пропорции одинаковые, слои совпадают в рамке. Попутно: видимое фото легче (пример 228 → 146 KB).

## 2026-11-01 — Видимый знак на витрине выключен (решение владельца)
- `MEDIA_WATERMARK=off`: фото на сайте (каталог, корзина, карточка, og) — без знака. Логотипы остаются только на копии «для сохранения» (`MEDIA_WATERMARK_SAVE=corners`) и на `/admin/media/{имя фото товара}`. Код не менялся — только настройка.
- Следствие (осознанно принято): чистая копия 1200px доступна по прямому адресу `?size=card` — её заберёт тот, кто полезет в DevTools/скрипт. Обычное «Сохранить картинку» отдаёт копию с логотипами.

## 2026-11-01 — Сохраняемая копия: логотипы во всех углах и по центру (в коде, до деплоя)
- По выбору владельца режим `triple` заменён на `corners`: пять логотипов ~25% ширины — четыре угла + центр. Обрезкой краёв или центра знак не убрать.

## 2026-11-01 — Знак читается на тёмных фото + режим «три логотипа» (в коде, до деплоя)
- Владелец скачал фото — «знака нет»: он был, но синий логотип при 45% растворялся на тёмной/пёстрой картинке (проверено на скачанной копии). Добавлена белая обводка логотипа; версия оформления (`_MARK_STYLE=2`) входит в имя копии → копии пересоздаются.
- Новый режим `triple` — три логотипа по диагонали (обрезкой угла не убрать). Расположение для сохраняемой копии (`center`/`triple`) — за владельцем.
- Проверка: 321 тест (+2: три метки на диагонали, видимость на чёрном фото).

## 2026-11-01 — «Сохранить картинку» отдаёт фото с крупным логотипом (в коде, до деплоя)
- На витрине — лёгкий знак в углу (`MEDIA_WATERMARK_OPACITY=0.2`); поверх большого фото на карточке — невидимый слой с копией `size=save` (крупный логотип по центру, `MEDIA_WATERMARK_SAVE`/`_SAVE_OPACITY`). Правый клик → «Сохранить», долгое нажатие и перетаскивание берут верхний слой.
- Совсем чистой копии наружу нет нигде: и видимая, и сохраняемая — со знаком. `/admin/media/{имя фото товара}` теперь отдаёт `save`.
- Проверка: 319 тестов; в браузере (десктоп + мобильная ширина) слой — верхний элемент на всей площади фото, стрелки галереи над ним; память — пик ~240 MB при 3 размерах × 40 потоков.

## 2026-11-01 — Водяной знак (логотип) на фото товаров (в коде, до деплоя)
- Фото снимает владелец (а не поставщики, как ошибочно предполагалось по EXIF) — на всех копиях фото товаров (thumb/card/og) логотип `backend/app/assets/watermark.png`, `MEDIA_WATERMARK=off|corner|center`, `MEDIA_WATERMARK_OPACITY` (0.4). Баннеры/бренды/иконки — без знака.
- Обходной путь `/admin/media/{имя фото товара}` теперь отдаёт ту же копию `card` со знаком (проверка привязки к товару в БД, сессия закрывается до работы с файлом).
- Проверка: 317 тестов зелёные (+10), память с знаком — пик ~190 MB.
