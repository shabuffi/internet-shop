# 01. Обзор и поток данных

## Идея проекта одним абзацем

МойСклад — «хозяин» каталога (товары, цены, остатки ведутся там). Наш магазин —
витрина, которая **зеркалит** этот каталог и принимает заказы. Товары едут только
в одну сторону: МойСклад → магазин. Заказы — в обратную: магазин → МойСклад.
Магазин ничего не выдумывает про товары, он лишь копия каталога в своей БД.

## 7 сервисов (docker-compose.yml)

| Сервис | Что это | Порт | Роль |
|--------|---------|------|------|
| `backend` | Python 3.12 / FastAPI | 8000 | REST API + приёмник CommerceML |
| `worker` | тот же образ | — | Celery worker (фоновые задачи) |
| `beat` | тот же образ | — | Celery beat (задачи по расписанию) |
| `db` | postgres:16 | 5432 | Основная база |
| `redis` | redis:7 | 6379 | Брокер Celery + состояние обмена |
| `frontend` | node:20 / Next.js 15 | 3000 | Витрина (SSR) |
| `nginx` | nginx:alpine | 80 | Прокси: `/api/*` → backend, остальное → frontend |

**Важно про nginx:** браузер всегда стучится на порт 80. Если путь начинается с
`/api/` — nginx отдаёт запрос бэкенду, иначе — фронтенду. Поэтому в браузере
картинка `/api/v1/products/{id}/image` уходит на backend, а страница `/` — на Next.js.

## Три главных потока данных

### Поток 1: каталог из МойСклад в магазин

```
МойСклад ──CommerceML XML──▶ /api/v1/1c/exchange ──▶ парсер ──▶ upsert_catalog() ──▶ таблица products
```

МойСклад сам инициирует обмен по расписанию (или по кнопке). Он шлёт XML с товарами
и отдельно XML с ценами/остатками. Наш бэкенд их парсит и складывает в БД.
Подробно — в [02-обмен-commerceml.md](02-обмен-commerceml.md) и [03-импорт-и-каталог.md](03-импорт-и-каталог.md).

### Поток 2: покупатель смотрит витрину

```
Браузер ──▶ Next.js (SSR) ──▶ GET /api/v1/products ──▶ таблица products ──▶ HTML обратно в браузер
```

Страницы витрины — серверные компоненты Next.js. Они на сервере дёргают наш API,
получают товары и отдают готовый HTML. Подробно — в [04-витрина-картинки.md](04-витрина-картинки.md).

### Поток 3: заказ от покупателя в МойСклад

```
Браузер ──форма──▶ POST /api/v1/orders ──▶ таблица orders ──▶ Celery-задача ──▶ REST API МойСклад
```

Заказ сначала сохраняется в нашу БД (быстро, синхронно), а отправка в МойСклад идёт
фоном через Celery — чтобы покупатель не ждал. Подробно — в [05-заказы.md](05-заказы.md).

## Где что лежит — backend (`backend/app/`)

```
main.py                  ← сборка FastAPI-приложения, подключение роутеров, CORS
core/
  config.py              ← Settings (читает .env): БД, Redis, SECRET_KEY, креды МойСклад
  redis_client.py        ← общий Redis-клиент (для состояния обмена)
db/
  session.py             ← движок SQLAlchemy, SessionLocal, Base, get_db
  models/
    product.py           ← Product, Category, SyncLog
    order.py             ← Order, OrderItem
    admin.py             ← AdminUser, ShopSettings
api/v1/endpoints/
  exchange.py            ← приём CommerceML от МойСклад (обмен)
  products.py            ← витрина: список, карточка, категории, прокси картинок
  orders.py              ← приём заказов с витрины
  admin.py               ← вся админка: вход, настройки, заказы, синхронизация
schemas/                 ← Pydantic-модели запросов/ответов (отдельно от ORM)
  product.py, order.py
services/
  import_service.py      ← upsert_catalog(): кладёт распарсенный каталог в БД
integrations/moysklad/
  commerceml_parser.py   ← разбор XML (lxml) → ParsedCatalog
  rest_client.py         ← клиент REST API МойСклад (картинки, заказы)
tasks/
  celery_app.py          ← конфиг Celery + расписание beat
  sync.py                ← фоновые задачи: картинки, отправка заказов, (стаб) синхронизация
```

## Где что лежит — frontend (`frontend/src/`)

```
app/
  layout.tsx             ← общий каркас (шапка с названием магазина)
  page.tsx               ← каталог: сетка товаров + поиск + фильтр + пагинация
  products/[id]/page.tsx ← карточка товара
  cart/page.tsx          ← корзина
  checkout/page.tsx      ← оформление заказа
  checkout/success/      ← страница «спасибо за заказ»
  admin/                 ← админка (login, settings, orders, products, sync)
components/
  CartContext.tsx        ← корзина в localStorage (React Context)
  AddToCartButton.tsx, CartIcon.tsx, AdminShell.tsx
lib/
  api.ts                 ← обёртки fetch для витрины
  adminApi.ts            ← обёртки fetch для админки (с JWT-токеном)
types/product.ts         ← TypeScript-типы (совпадают с Pydantic-схемами)
```

## Ключевой принцип идентификации товара

У товара ДВА id:
- `Product.moysklad_id` — UUID из МойСклад. **Стабильный ключ** — по нему обновляем
  товар при каждой синхронизации (upsert).
- `Product.id` — наш внутренний UUID. По нему витрина строит ссылки (`/products/{id}`).

Когда отправляем заказ обратно в МойСклад, товар там ищется **по артикулу**
(`article`), а не по id — потому что id из CommerceML и id из REST API у этого
аккаунта в разных форматах. См. [05-заказы.md](05-заказы.md).
