# 07. Что уже готово и что осталось

Состояние на текущую сессию.

## ✅ Готово и проверено

**Базовый цикл MVP:**
- Приём каталога из МойСклад (CommerceML) — товары, категории, цены, остатки, описания.
- Витрина: каталог, фильтр по категориям, **поиск**, **пагинация**, карточка товара.
- Корзина (localStorage) → оформление → заказ в БД → отправка в МойСклад (фоном, с ретраями).
- Картинки: колонка `image_url`, прокси-эндпоинт, Celery-задача, кнопка в админке.
- Админка: вход (JWT+bcrypt), дашборд, товары, заказы, настройки, логи синхронизации.

**Закрыто в этой сессии (P0 — безопасность и устойчивость):**
1. ✅ **Дыра в обмене** — теперь сайт сверяет логин/пароль обмена (набор ①).
   «Мягкий режим» не ломает текущий обмен: проверка включается, когда пара задана в админке.
2. ✅ **Состояние обмена → Redis** — переживает перезапуск backend и работает при
   нескольких воркерах. Раньше лежало в памяти процесса.
3. ✅ Миграция `image_url` применена.

**Закрыто в этой сессии (P1):**
4. ✅ **Управление статусом заказа** в админке (выпадающий список + PATCH-эндпоинт).
5. ✅ **Поиск** на витрине.
6. ✅ **Пагинация** на витрине.

**Закрыто в этой сессии (P2):**
7. ✅ **Кэш картинок** — два слоя: `Cache-Control` (браузер кэширует на сутки) +
   байты в Redis на сутки (`image:data:{id}` / `image:ct:{id}`). Прокси больше не
   дёргает МойСклад на каждый показ. Заголовок `X-Cache: HIT/MISS` для отладки.
8. ✅ **Чистка `sync_interval` / `sync_catalog`** — удалены: пустая задача-заглушка
   `sync_catalog`, её расписание в beat, нерабочее поле «интервал синхронизации» в
   админке и `SYNC_INTERVAL_SECONDS` из конфига. Расписание beat теперь пустое
   (модель push: каталог шлёт МойСклад, картинки — по кнопке). Persistent-файл
   `celerybeat-schedule` пересоздан с чистого листа.
9. ✅ **Тесты (pytest)** — 38 тестов: парсер CommerceML, `upsert_catalog`, создание
   заказа, смена статуса, аутентификация обмена, авторизация админки. Запуск:
   `make test`. Тестовая БД — SQLite в памяти (`backend/tests/conftest.py`). pytest
   добавлен в `requirements-dev.txt` и Dockerfile.
   - 🐛 **Заодно найден и исправлен баг:** `upsert_catalog` проставлял `parent_id`
     категорий повторным запросом в БД, который при `autoflush=False` (как в проде)
     не находил свежедобавленные категории — связь родитель-потомок не ставилась с
     первой синхронизации. Исправлено: проставляем по объектам в памяти.
10. ✅ **Чистка deprecation** — `datetime.utcnow()` (устарел) заменён на хелпер
    `_utcnow()` в `import_service.py`. Тесты идут без warning'ов.
11. ✅ **Безопасность** — (а) JWT админа теперь в **httpOnly-куке**, а не в
    localStorage (защита от XSS); добавлены `/admin/logout` и `/admin/me`; фронт
    проверяет сессию через `/me`. (б) `exchange_password` хранится **bcrypt-хешем**
    (раньше — открытым текстом). `moysklad_password` остаётся открытым осознанно —
    он исходящий, нужен для запросов к МойСклад.

**Доработки по ревью** (`fastapi-reviewer` / `react-reviewer`):

## ⏳ Осталось

### P1 — нужно клиенту для реальной работы

**Уведомление о новом заказе.** Сейчас заказ молча падает в БД — владелец узнает,
только открыв админку. Нужно оповещение (email или Telegram) при создании заказа.
Точка вставки готова: `create_order` в [orders.py](../backend/app/api/v1/endpoints/orders.py)
уже вызывает Celery — туда же добавить задачу `notify_new_order`.
*Требует решения: канал (email через SMTP / Telegram-бот) и доступы.*

### P2 — качество и устойчивость

- **`secure=True` для куки админа** — сейчас `secure=False`, т.к. сайт на HTTP.
  Когда переедет на HTTPS — включить (см. `COOKIE` в `admin.py`).
- **`moysklad_password` в БД открытым текстом** — он исходящий, хешировать нельзя;
  при желании можно шифровать (encryption-at-rest с ключом из окружения).

## 📌 Операционные напоминания

- После изменения Celery-задач: `docker compose restart worker` (воркер не
  перечитывает код на лету).
- Чтобы включить защиту обмена: задать `exchange_login`/`exchange_password` в админке
  **и** ту же пару в МойСклад (Онлайн-торговля → Адрес магазина).
- Картинки наполняются по кнопке «Загрузить картинки» (батчами по 50).
