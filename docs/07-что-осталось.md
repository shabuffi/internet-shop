# 07. Что уже готово и что осталось

Актуальное состояние проекта.

## ✅ Готово и проверено

**Интеграция — только CommerceML (без пароля аккаунта МойСклад):**
- **Каталог/остатки/описания вниз** — обмен CommerceML (import.xml + offers.xml).
- **Картинки вниз** — приходят файлами обмена в медиа-хранилище (том `media_data`),
  отдаются прокси-эндпоинтом. REST/пароль аккаунта не нужны.
- **Заказы вверх** — МойСклад сам забирает (`type=sale&mode=query/success`), помечаем
  `exported_at`; контрагента и резерв создаёт сам МойСклад. См. [02](02-обмен-commerceml.md), [05](05-заказы.md).
- Гард `has_offer`: import.xml без offers (второй заход с картинкой) не обнуляет цену/остаток.

**Базовый цикл MVP:**
- Витрина: каталог, фильтр по категориям, поиск, пагинация, карточка товара. Дизайн «Контур».
- Корзина (localStorage) → оформление (имя+фамилия) → заказ в БД → списание остатка → уведомление.
- **Анти-oversell** — атомарное списание остатка при заказе (`UPDATE … WHERE stock >= qty`),
  409 при нехватке; на витрине «Нет в наличии» и потолок количества. Отмена возвращает остаток.
- Админка: вход (JWT в httpOnly-куке + bcrypt), дашборд, товары, заказы (статус + «Выгрузка»), настройки, логи.

**Безопасность и устойчивость:**
- Аутентификация обмена, «мягкий режим»; состояние обмена в Redis (переживает перезапуск,
  работает при нескольких воркерах). `exchange_password` — bcrypt-хеш; whitelist имён файлов.
- JWT админа в httpOnly-куке; смена пароля админа через UI; статус заказа на Pydantic-`Literal`.

**Уведомления о заказах:**
- `notify_new_order` — при создании заказа шлёт владельцу в **Telegram и/или ВК** (мгновенно,
  не дожидаясь, пока МойСклад заберёт заказ). См. [05-заказы.md](05-заказы.md).

**Тесты:**
- Backend: **pytest**, 73 теста (парсер, импорт, заказы + списание остатка, статусы/отмена,
  выдача заказов CommerceML, приём картинок, уведомления, аутентификация). Запуск: `make test`.
- Frontend: **Playwright E2E**, путь покупки + каталог/карточка. Запуск: `make test-e2e`.
  Сид тестового товара с фейковым артикулом — без следов в МойСклад. См.
  [../frontend/e2e/README.md](../frontend/e2e/README.md).

**Деплой:** на VPS (Selectel), reachable для МойСклад; `deploy.sh` (миграции + перезапуск).

## ⏳ Осталось

### P1 — нужно для боевой работы
- **HTTPS + домен.** Сайт на HTTP/IP: пароль админа и данные покупателей идут открытым
  текстом, куки `secure=False`. Нужен домен + TLS (Let's Encrypt/nginx), затем `secure=True`
  (см. `COOKIE` в [admin.py](../backend/app/api/v1/endpoints/admin.py)).

### P2 — качество и устойчивость
- **Реальные контакты в подвале** — сейчас заглушки `+7 (999) 000-00-00`, `info@example.ru`.
- **Письмо-подтверждение покупателю** — уведомления есть только владельцу.
- **CI** — прогонять `make test` и Playwright автоматически на push (пока вручную).
- **Проброс отмены заказа в МойСклад** — при отмене на сайте локальный остаток возвращается,
  но резерв в МойСклад снимают вручную; можно выгружать изменения статусов обменом.

### P3 — приятно иметь
- **SEO** — meta-теги, sitemap, robots.
- **Мониторинг ошибок** (Sentry) + rate-limiting на API.

## 📌 Операционные напоминания

- **Пароль аккаунта МойСклад больше не нужен.** Интеграция на чистом CommerceML; в магазине
  только пара обмена (`exchange_login`/`exchange_password`).
- Настройки МойСклад (Онлайн-торговля): включить выгрузку **остатков** и **изображений**,
  загрузку **заказов** («Включить загрузку») и **«Резервировать товары»**. Интервал загрузки
  заказов — на твой вкус (1–5 мин): заказ появляется в МойСклад с этой задержкой (pull).
- Защита обмена включается, когда `exchange_login`/`exchange_password` заданы в админке
  **и** та же пара в МойСклад (Онлайн-торговля → Адрес магазина).
- **Остатки на проде:** анти-oversell блокирует заказ при `stock = 0`. Убедиться, что
  обмен `offers.xml` реально присылает количество (`<Количество>`).
- Уведомления: задать токены в админке → Настройки → «Уведомления о заказах».
- После изменения кода Celery-задач: `docker compose restart worker`.
- **Бэкапы БД:** `make backup` (или `./scripts/backup-db.sh`) → дамп в `./backups` с ротацией.
  На сервере поставить в cron (ежедневно):
  `0 3 * * * cd /opt/internet-shop && ./scripts/backup-db.sh >> /var/log/shop-backup.log 2>&1`
  Восстановить: `gunzip -c backups/db_XXXX.sql.gz | docker compose --env-file .env.prod -f docker-compose.prod.yml exec -T db psql -U <user> <db>`.
  ⚠️ Для надёжности дампы стоит копировать и **вне сервера** (S3/другой хост).
