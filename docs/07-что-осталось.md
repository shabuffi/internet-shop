# 07. Что уже готово и что осталось

Актуальное состояние проекта.

## ✅ Готово и проверено

**Базовый цикл MVP:**
- Приём каталога из МойСклад (CommerceML) — товары, категории, цены, остатки, описания.
- Витрина: каталог, фильтр по категориям, поиск, пагинация, карточка товара. Дизайн «Контур».
- Корзина (localStorage) → оформление → заказ в БД → отправка в МойСклад (фоном, с ретраями).
- Картинки: колонка `image_url`, прокси-эндпоинт с кэшем (браузер + Redis), Celery-задача.
- Админка: вход (JWT в httpOnly-куке + bcrypt), дашборд, товары, заказы, настройки, логи.

**Безопасность и устойчивость:**
- Аутентификация обмена (набор ①), «мягкий режим»; состояние обмена в Redis (переживает
  перезапуск, работает при нескольких воркерах).
- `exchange_password` хранится bcrypt-хешем; JWT админа в httpOnly-куке; whitelist имён
  файлов обмена; статус заказа на Pydantic-`Literal`.
- Смена пароля админа через UI (`/admin/change-password`).

**Связка склад ↔ сайт (надёжность заказов и каталога):**
- **REST-id товара** (`moysklad_rest_id`) — заказы уезжают по сохранённому id, без поиска
  по артикулу на каждую позицию.
- **Досинхронизация зависших заказов** — beat-задача `resync_pending_orders` (каждые 10
  мин) пере-отправляет заказы без `moysklad_id`; в админке кнопка «Повторить».
- **Анти-oversell** — атомарное списание остатка при заказе (`UPDATE … WHERE stock >= qty`),
  409 при нехватке; на витрине «Нет в наличии» и потолок количества.
- **Автообогащение по расписанию** — beat-задача `fetch_product_images` (каждые 15 мин)
  дотягивает картинку/описание/`rest_id` для новых товаров; ручная кнопка осталась.

**Уведомления о заказах:**
- `notify_new_order` — при создании заказа шлёт владельцу в **Telegram и/или ВК** (что
  настроено в админке). См. [05-заказы.md](05-заказы.md).

**Тесты:**
- Backend: **pytest**, 60 тестов (парсер, импорт, заказы + списание остатка, статусы,
  досинхронизация, уведомления, аутентификация обмена/админки). Запуск: `make test`.
- Frontend: **Playwright E2E**, путь покупки + каталог/карточка. Запуск: `make test-e2e`.
  Сид тестового товара с фейковым артикулом — без следов в МойСклад. См.
  [../frontend/e2e/README.md](../frontend/e2e/README.md).

**Деплой:** на VPS (Selectel), reachable для МойСклад; `deploy.sh` (миграции + перезапуск).

## ⏳ Осталось

### P1 — нужно для боевой работы
- **HTTPS + домен.** Сайт на HTTP/IP: пароль админа и данные покупателей идут открытым
  текстом, куки `secure=False`. Нужен домен + TLS (Let's Encrypt/nginx), затем `secure=True`
  (см. `COOKIE` в [admin.py](../backend/app/api/v1/endpoints/admin.py)).

### P2 — качество и устойчивость
- **Реальные контакты в подвале** — сейчас заглушки `+7 (999) 000-00-00`, `info@example.ru`.
- **Возврат остатка при отмене заказа** — при отмене в админке локальный `stock` не
  возвращается (ждём пере-синхронизацию из МойСклад).
- **Письмо-подтверждение покупателю** — уведомления есть только владельцу.
- **CI** — прогонять `make test` и Playwright автоматически на push (пока вручную).
- **Шифрование `moysklad_password`** в БД (исходящий, хешировать нельзя — encryption-at-rest).

### P3 — приятно иметь
- **Webhooks из МойСклад** — остатки/цены в реальном времени вместо ожидания обмена.
- **SEO** — meta-теги, sitemap, robots.
- **Мониторинг ошибок** (Sentry) + rate-limiting на API.

## 📌 Операционные напоминания

- После изменения Celery-задач: `docker compose restart worker` (воркер не перечитывает
  код на лету). Для расписания — ещё и `restart beat`.
- Защита обмена включается, когда `exchange_login`/`exchange_password` заданы в админке
  **и** та же пара в МойСклад (Онлайн-торговля → Адрес магазина).
- **Остатки на проде:** анти-oversell блокирует заказ при `stock = 0`. Убедиться, что
  обмен `offers.xml` реально присылает количество (`<Количество>`), иначе заказы не пройдут.
- Уведомления: задать токены в админке → Настройки → «Уведомления о заказах».
