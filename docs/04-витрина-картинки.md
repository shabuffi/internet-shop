## Эндпоинты витрины (`/api/v1/products`)

Порядок объявления маршрутов важен! `/categories` и `/{id}/image` объявлены **до**
`/{product_id}`, иначе FastAPI принял бы «categories» за id товара.

### `GET /products` — список с фильтром, поиском, пагинацией

```python
query = select(Product).options(joinedload(Product.category)).where(Product.is_active == True)
if category_id:
    query = query.where(Product.category_id == category_id)
if search:
    pattern = f"%{search}%"
    query = query.where(Product.name.ilike(pattern) | Product.article.ilike(pattern))
total = db.scalar(select(func.count()).select_from(query.subquery()))
items = db.scalars(query.offset((page-1)*page_size).limit(page_size)).all()
```

- `is_active == True` — показываем только активные товары.
- `joinedload(Product.category)` — сразу подтягиваем категорию одним запросом (без
  лишних обращений к БД на каждый товар).
- `ilike` — поиск без учёта регистра по названию **или** артикулу.
- Возвращает `ProductListOut`: items + total + page + page_size + pages.

### `GET /products/categories` — список категорий для чипов фильтра

Просто все категории, отсортированные по имени.

### `GET /products/{id}` — карточка одного товара

Один товар по нашему внутреннему `id`, тоже с подгруженной категорией. 404 если нет
или неактивен.

### `GET /products/{id}/image` — отдача картинки из медиа-хранилища ⭐

Картинки приходят **файлами в обмене CommerceML** и лежат на диске (том `media_data`,
каталог `MEDIA_DIR`). `Product.image_url` — это **имя файла**. Эндпоинт просто отдаёт
байты из хранилища, без обращения к МойСклад и без пароля аккаунта:

```python
@router.get("/{product_id}/image")
def get_product_image(product_id, db):
    product = db.scalar(select(Product).where(Product.id == product_id, Product.is_active == True))
    if not product or not product.image_url:
        raise HTTPException(404, "Изображение не найдено")
    result = read_image(product.image_url)            # media_storage: байты + content-type
    if result is None:
        raise HTTPException(404, "Изображение не найдено")
    data, content_type = result
    return Response(content=data, media_type=content_type,
                    headers={"Cache-Control": "public, max-age=86400"})
```

Кэш — браузерный (`Cache-Control` на сутки). Сами байты локальны и отдаются быстро, так
что Redis-слой для картинок не нужен.

## Откуда берётся `image_url`

Картинки приезжают **через обмен CommerceML** (опция «Выгружать изображения» в МойСклад).
Цепочка:

```
МойСклад выгрузка каталога (с картинками)
   └▶ POST /api/v1/1c/exchange?mode=file&filename=<uuid>_imageid.png   (файл картинки)
        └▶ media_storage.save_image() → файл в MEDIA_DIR (том media_data)
   └▶ import.xml содержит <Картинка><uuid>_imageid.png</Картинка>
        └▶ upsert_catalog: Product.image_url = basename(<Картинка>)
```

То есть `<Картинка>` в import.xml связывает товар с файлом по **имени** (basename), а сам
файл прилетает отдельным POST'ом обмена. Прокси-эндпоинт потом отдаёт его из хранилища.

> Раньше картинки тянулись из REST API МойСклад (с паролем аккаунта). После перехода на
> чистый CommerceML REST убран — картинки идут только обменом.

## Фронтенд: каталог `page.tsx`

Это **серверный компонент** (нет `"use client"`). Весь рендер — на сервере, в браузер
едет готовый HTML. Преимущество: поиск/фильтр/пагинация работают **без клиентского JS**.

### Как сохраняются параметры в URL

Состояние (категория, поиск, страница) живёт **в URL**, не в React-стейте. Хелпер
собирает ссылки:

```tsx
function buildHref({ category_id, search, page }) {
  const q = new URLSearchParams();
  if (category_id) q.set("category_id", category_id);
  if (search) q.set("search", search);
  if (page && page > 1) q.set("page", String(page));
  return q.toString() ? `/?${q}` : "/";
}
```

- **Чипы категорий** — это `<Link>` на `buildHref({category_id, search})`. При клике
  сохраняется текущий поиск, страница сбрасывается (page не передаётся → 1).
- **Поиск** — обычная HTML-форма `<form action="/" method="get">`. При сабмите
  навигирует на `/?search=...`. Чтобы не потерять выбранную категорию — она кладётся
  скрытым полем `<input type="hidden" name="category_id">`. Страница тоже сбрасывается
  (нет hidden-поля page).
- **Пагинация** — две ссылки «Назад/Вперёд» на `buildHref({..., page: page±1})`,
  сохраняют и категорию, и поиск.

### Картинка или эмодзи

```tsx
{product.image_url ? (
  <img src={`/api/v1/products/${product.id}/image`} alt={product.name} ... />
) : (
  <span style={{...}}>🛍</span>
)}
```

Если у товара есть `image_url` — показываем картинку (через прокси-эндпоинт), иначе
заглушку-эмодзи. (Раньше тут был `onError`-обработчик, но в серверном компоненте
обработчики событий запрещены — убрали, оставили чистое условие.)

### Получение данных без «водопада»

```tsx
const [data, categories] = await Promise.all([
  getProducts({ category_id, search, page }),
  getCategories(),
]);
```

Товары и категории грузятся **параллельно** (`Promise.all`), а не одно за другим.

## Карточка товара `products/[id]/page.tsx`

Тоже серверный компонент. Берёт `getProduct(id)`, показывает большую картинку (или
эмодзи), имя, артикул, цену, описание, наличие и кнопку «в корзину»
(`AddToCartButton` — это уже клиентский компонент, потому что работает с корзиной в
localStorage). Если товара нет — `notFound()` (страница 404).
