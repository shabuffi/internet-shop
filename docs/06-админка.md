# 06. Админка: вход, настройки, данные

Бэкенд: [admin.py](../backend/app/api/v1/endpoints/admin.py).
Модели: [db/models/admin.py](../backend/app/db/models/admin.py) — `AdminUser`, `ShopSettings`.
Фронтенд: `frontend/src/app/admin/*`, обёртка fetch — [lib/adminApi.ts](../frontend/src/lib/adminApi.ts).

Все эндпоинты под префиксом `/api/v1/admin`.

## Зачем вообще нужна админка

Чтобы клиент, для которого делается сайт, **сам вводил свои данные** (логины/пароли
МойСклад, название магазина) через интерфейс — а не передавал их разработчику для
вставки в `.env`. Настройки хранятся в БД (таблица `ShopSettings`), а `.env` остаётся
запасным вариантом.

## Аутентификация: JWT + bcrypt

### Пароль администратора — bcrypt

Пароль админа не хранится в открытом виде. Хранится bcrypt-хеш:

```python
def _hash_password(password):  return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()
def _verify_password(p, hashed): return bcrypt.checkpw(p.encode(), hashed.encode())
```

### Токен входа — JWT

При успешном входе выдаётся JWT-токен на 24 часа, подписанный `SECRET_KEY`:

```python
def _create_token(username):
    payload = {"sub": username, "exp": datetime.now(timezone.utc) + timedelta(hours=24)}
    return jwt.encode(payload, settings.SECRET_KEY, algorithm="HS256")
```

При логине сервер кладёт JWT в **httpOnly-куку** `admin_token` (`/admin/login`,
`response.set_cookie(..., httponly=True)`). httpOnly = кука недоступна из JavaScript →
её не украсть через XSS. Токен в `localStorage` больше не хранится. На бэкенде защита
маршрута — зависимость `_get_current_admin`:

```python
def _extract_token(request):       # сначала кука, потом заголовок Authorization (для тестов/API)
    return request.cookies.get(COOKIE_NAME) or _bearer_from_header(request)

def _get_current_admin(request, db):
    token = _extract_token(request)
    if not token: raise HTTPException(401, "Не авторизовано")
    payload = jwt.decode(token, settings.SECRET_KEY, algorithms=["HS256"])
    user = db.scalar(select(AdminUser).where(AdminUser.username == payload.get("sub")))
    if not user: raise HTTPException(401, ...)
    return user
```

Любой эндпоинт с `_=Depends(_get_current_admin)` доступен только с валидной кукой
(или Bearer-токеном). Выход — `POST /admin/logout` (сбрасывает куку). Фронт проверяет
сессию через `GET /admin/me` (кука httpOnly из JS не читается, поэтому спрашиваем сервер).

⚠️ Кука сейчас с `secure=False`, т.к. сайт на HTTP. На HTTPS — поставить `secure=True`.

### Создание первого админа — `/setup`

`POST /admin/setup` создаёт первого пользователя, но **только если админов ещё нет**
(потом отдаёт 400). Используется один раз при развёртывании.

## Настройки — таблица `ShopSettings` (ключ-значение)

`ShopSettings` — простая таблица «ключ → значение». Хелперы:

```python
def _get_setting(db, key, default=""):  row = db.get(ShopSettings, key); return row.value if row else default
def _set_setting(db, key, value):       # создаёт или обновляет строку
```

### `GET /admin/settings` и `POST /admin/settings`

Хранятся ключи (пароля аккаунта МойСклад **нет** — интеграция на чистом CommerceML):

| Ключ | Что это |
|------|---------|
| `exchange_login` | логин обмена CommerceML (придуманный, лишь бы совпадал) |
| `exchange_password` | пароль обмена (придуманный) |
| `shop_name` | название магазина (в шапке сайта) |
| `telegram_bot_token` / `telegram_chat_id` | уведомления в Telegram |
| `vk_group_token` / `vk_peer_id` | уведомления во ВКонтакте |

**Маскировка секретов:** в `GET` токены/пароли отдаются как `"***"`. В `POST` значение
`"***"` пропускается («оставить как было»). `exchange_password` при сохранении
**хешируется** (bcrypt); токены уведомлений — открытым текстом (исходящие):

```python
for key, value in body.items():
    if key not in allowed or value == "***":
        continue
    if key == "exchange_password":
        _set_setting(db, key, _hash_password(str(value)))   # bcrypt-хеш
    else:
        _set_setting(db, key, str(value))
```

### Где эти настройки реально используются

- `exchange_login/password` → `exchange._get_exchange_credentials()` (проверка обмена).
- токены уведомлений → `notify.get_notify_config()` (Telegram/ВК).
- `shop_name` → витрина показывает в шапке (`GET /admin/store-info` — публичный эндпоинт).

## Остальные эндпоинты админки

| Эндпоинт | Что отдаёт |
|----------|-----------|
| `POST /admin/login` | вход → JWT-токен |
| `GET /admin/dashboard` | счётчики: товаров, заказов, последняя синхронизация |
| `GET /admin/orders` | список заказов (пагинация по 20) |
| `PATCH /admin/orders/{id}/status` | сменить статус заказа (см. [05-заказы.md](05-заказы.md)) |
| `GET /admin/products` | список товаров (пагинация по 50) |
| `GET /admin/sync-logs` | история синхронизаций (последние 20) |
| `GET /admin/store-info` | **публичный** — название магазина для витрины |

(Эндпоинты `test-connection`, `fetch-images`, `orders/{id}/resync` удалены вместе с REST —
проверять подключение к аккаунту и докачивать картинки больше не нужно.)

## Фронтенд админки

- `adminApi.ts` — обёртка `adminFetch`: подставляет токен, при `401` чистит токен и
  редиректит на `/admin/login`.
- `admin/settings/page.tsx` — форма настроек с тремя секциями (доступ к API,
  данные обмена, синхронизация) и кнопкой «Проверить подключение».
- `admin/orders/page.tsx` — таблица заказов с редактируемым статусом.
- `admin/sync/page.tsx` — лог синхронизаций + кнопки «Загрузить картинки»/«Обновить».
- `admin/products/page.tsx` — список товаров.

## Памятка по безопасности (текущее состояние)

- Пароль админа — bcrypt ✅. Токен — JWT с истечением ✅.
- Токен админа — в **httpOnly-куке** ✅ (не в localStorage → защита от XSS).
- `exchange_password` — **bcrypt-хеш** в БД ✅.
- Пароль аккаунта МойСклад **не хранится** — интеграция на чистом CommerceML ✅.
- Токены уведомлений (ТГ/ВК) — открытым текстом (исходящие секреты).
- Кука сейчас `secure=False` (сайт на HTTP). На HTTPS включить `secure=True`.
