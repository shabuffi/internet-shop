# 03. Импорт каталога: из XML в таблицы

Два файла:
- [commerceml_parser.py](../backend/app/integrations/moysklad/commerceml_parser.py) — превращает XML в Python-объекты.
- [import_service.py](../backend/app/services/import_service.py) — кладёт эти объекты в БД (upsert).

## Шаг А: парсинг XML → `ParsedCatalog`

Парсер не трогает БД. Его задача — разобрать байты XML в простые структуры данных
(`@dataclass`):

```python
@dataclass
class ParsedCategory:    moysklad_id; name; parent_id
@dataclass
class ParsedProduct:     moysklad_id; name; description; article; code; category_id; price; stock
@dataclass
class ParsedCatalog:     categories: list[ParsedCategory]; products: list[ParsedProduct]
```

### `parse_import_xml(xml_bytes)` — товары и категории

Разбирает `import.xml`:
1. `_detect_ns(root)` — определяет namespace (у МойСклад его нет → пустая строка).
2. Из блока `<Классификатор><Группы>` рекурсивно собирает дерево категорий
   (`_parse_groups`).
3. Из блока `<Каталог><Товары>` по каждому `<Товар>` собирает `ParsedProduct`
   (`_parse_product`) — берёт `Ид`, `Наименование`, `Описание`, `Артикул` и первую
   группу как `category_id`.

Цены и остатки на этом шаге ещё **нулевые** — они придут отдельным файлом.

### `parse_offers_xml(xml_bytes, catalog)` — цены и остатки

Разбирает `offers.xml` и **дописывает** price/stock прямо в уже существующие
`ParsedProduct` (находит их по `moysklad_id`):

```python
product_index = {p.moysklad_id: p for p in catalog.products}
for предложение in offers_el.findall(_tag("Предложение", ns)):
    offer_id = _text(предложение, "Ид", ns=ns)
    base_id = offer_id.split("#")[0]           # у вариаций id вида "uuid#размер"
    product = product_index.get(base_id)
    ...
    product.price = Decimal(price_str.replace(",", "."))
    product.stock = int(float(qty_str))
```

**Про цену:** код берёт число как есть (`Decimal(price_str)`) — **без деления на 100**.
У этого аккаунта МойСклад присылает цену в рублях сразу. (В комментарии модели
`product.py` написано про «копейки/делим на 100» — это неактуально для текущего
аккаунта, фактический код не делит.)

### Почему `_detect_ns` и двойной поиск тегов

CommerceML по стандарту имеет namespace `urn:1C.ru:commerceml_2`, но МойСклад его не
шлёт. Хелпер `_text` сначала ищет тег с namespace, потом — без:

```python
def _text(element, tag, default=None, ns=""):
    child = element.find(_tag(tag, ns))
    if child is None and ns:
        child = element.find(tag)              # fallback без namespace
    ...
```

Так парсер работает с обоими вариантами XML.

## Шаг Б: `upsert_catalog(db, catalog)` — запись в БД

Upsert = «UPDATE если есть, INSERT если нет». Ключ совпадения — `moysklad_id`.

### 1. Сначала лог

```python
log = SyncLog(source=source, status="running", started_at=datetime.utcnow())
db.add(log); db.flush()
```

`SyncLog` — это строка в таблице, которую потом видно в админке на странице
«Синхронизация». Сначала статус `running`, в конце станет `success` или `error`.

### 2. Категории (в два прохода)

Первый проход — создать/обновить все категории и запомнить связь
`moysklad_id → наш internal id` в словаре `category_id_map`. Второй проход —
проставить `parent_id` (родителя), потому что родитель мог встретиться позже ребёнка:

```python
for parsed_cat in catalog.categories:
    cat = db.query(Category).filter_by(moysklad_id=parsed_cat.moysklad_id).first()
    if cat is None:
        cat = Category(id=str(uuid.uuid4()), moysklad_id=..., name=...)
        db.add(cat)
    else:
        cat.name = parsed_cat.name
    category_id_map[parsed_cat.moysklad_id] = cat.id
# второй проход — parent_id
```

### 3. Товары

По каждому `ParsedProduct` ищем существующий по `moysklad_id`:
- **нет** → создаём новый `Product`, `created += 1`.
- **есть** → перезаписываем поля (name, description, price, stock, …), `updated += 1`.

Категория товара переводится из «мойскладовского» id в наш через `category_id_map`.

### 4. Финал и обработка ошибок

```python
db.commit()
log.status = "success"; log.products_created = created; log.products_updated = updated
log.finished_at = datetime.utcnow(); db.commit()
```

Если на любом шаге исключение — `db.rollback()`, лог помечается `error` с текстом
ошибки, и исключение пробрасывается выше. То есть либо весь каталог записался, либо
ничего (транзакция).

## Что в итоге появляется в БД

- `categories` — дерево категорий (используется фильтром на витрине).
- `products` — товары: имя, описание, артикул, **цена в рублях**, остаток, категория.
  Поля `image_url` и `is_active` обмен **не трогает** (картинки приезжают отдельно
  через REST, см. [04-витрина-картинки.md](04-витрина-картинки.md)).
- `sync_logs` — по строке на каждую синхронизацию (видно в админке).

## Важный нюанс: периодической синхронизации НЕТ

Каталог (товары, цены, остатки, **картинки**) обновляется **только** когда МойСклад сам
инициирует обмен (push-модель из [02-обмен-commerceml.md](02-обмен-commerceml.md)).
Активной синхронизации со стороны магазина нет — и это сознательно. `beat_schedule`
пустой (см. [tasks/celery_app.py](../backend/app/tasks/celery_app.py)): фоновых задач по
расписанию больше нет, единственная Celery-задача — уведомление о заказе.
