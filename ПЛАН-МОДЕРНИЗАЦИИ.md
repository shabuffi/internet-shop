# План модернизации сайта ТД «ИНЖЕНЕР»

Документ описывает архитектуру сайта, что уже сделано, и план дальнейшего развития —
так, чтобы новые функции и изменения дизайна внедрялись **без серьёзных переделок**.

Дата: 21.06.2026.

---

## 1. Архитектура (почему сайт легко развивать)

Сайт построен на современном модульном стеке, каждый слой можно дорабатывать отдельно:

| Слой | Технология | Назначение |
|---|---|---|
| Витрина | Next.js 15 (React) | Страницы, SSR, SEO, адаптивность |
| API | FastAPI (Python) | Каталог, заказы, обмен с МойСклад |
| База | PostgreSQL | Товары, категории, заказы |
| Очереди | Celery + Redis | Уведомления, фоновые задачи |
| Прокси | Nginx | Маршрутизация, отдача статики |
| Всё в | Docker | Одинаковое окружение, простой деплой |

**Интеграция с МойСклад — только через CommerceML** (стандартный обмен 1С-Битрикс):
каталог, остатки, картинки, характеристики идут вниз; заказы — вверх. Пароль МойСклад не
используется. Это значит: меняется ассортимент/данные в МойСклад → сайт обновляется
автоматически, без участия разработчика.

**Точки расширения, заложенные в код** (правятся без переписывания):
- `frontend/src/lib/site.ts` — название, мин. сумма заказа и пр. константы;
- `frontend/src/lib/categoryGroups.ts` — какие категории каталога входят в плитки главной;
- `frontend/src/components/*` — переиспользуемые блоки (карта, рулетка, карточки, анимации);
- единый API-слой `frontend/src/lib/api.ts` — все запросы к бэкенду в одном месте;
- миграции БД (Alembic) — расширение модели без потери данных.

## 2. Что уже сделано (этап 1)

- **Главная:** баннер с реальной картой 6 областей доставки, бегущая строка регионов,
  блок 24/7 / мин. заказ / ассортимент / остатки, 8 плиток категорий с картинками, анимации.
- **Категории → каталог:** плитка ведёт в конкретный раздел (группа реальных категорий каталога).
- **Каталог:** фильтр по категориям и группам, сортировка, поиск (в т.ч. при неправильной
  раскладке: `vjq` → «мой»), режимы «плитка/список», заголовок раздела.
- **Карточка товара:** галерея, цена, кнопка, описание и **характеристики** (из свойств МойСклад) —
  в стиле маркетплейса.
- **Минимальный заказ 5 000 ₽:** показ + блокировка оформления (фронт и бэкенд).
- **«О компании» / «Контакты»:** официальные тексты, карта склада, оформление с иконками.
- **Надёжность прода:** автолечение зависаний (autoheal + таймауты), чистая сборка (`.dockerignore`).

## 3. Что зависит от наполнения МойСклад (на стороне заказчика)

Технически всё готово принимать данные, но сейчас в МойСклад они почти не заполнены:
**описания 0%, фото ~1%, характеристики 0% (только сертификаты), артикулы ~6%.**

Чтобы карточки и каталог «ожили», в МойСклад нужно заполнять:
- **описания** товаров;
- **фотографии** (минимум для ходовых позиций);
- **характеристики** — через *свойства* товара (вес, цвет, состав, размер…). Сайт уже умеет их
  показывать — появятся автоматически после ближайшего обмена.

Это не разработка, а контент-работа; её можно вести постепенно, начиная с топовых товаров.

## 4. План модернизации по блокам

### 4.1. Главная
- Промо-блоки/акции, управляемые из админки (без правки кода).
- Подборки: «Хиты», «Новинки», «Со скидкой» (нужны метки товаров в МойСклад/админке).
- Баннер-карусель под сезон (Новый год, дача, школа).
- *Архитектура готова:* блоки — отдельные компоненты, легко добавить на страницу.

### 4.2. Каталог и фильтры
- Фильтры по цене, наличию, бренду, фасовке (когда поля появятся в данных).
- Подкатегории-«хлебные крошки» и боковое меню разделов.
- Вычитка группировки категорий (`categoryGroups.ts`) с заказчиком — уже черновик из 139 категорий.
- *Архитектура готова:* бэкенд уже фильтрует по списку категорий; добавить новые фильтры — точечно.

### 4.3. Карточка товара
- Характеристики и модификации (размеры/цвета) — заработают из свойств МойСклад.
- Блок «С этим товаром покупают» / «Похожие».
- Быстрый заказ и «бланк заказа» прямо из карточки.
- *Архитектура готова:* поле характеристик и галерея уже есть.

### 4.4. Поиск
- Подсказки при вводе (автокомплит), поиск по артикулу и характеристикам.
- Исправление опечаток. (Неправильная раскладка — уже сделано.)

### 4.5. Визуал и UX
- Единая дизайн-система (цвета/типографика уже в `globals.css` как переменные).
- Тёмная тема, доработка мобильной версии.
- Микроанимации (часть уже есть: появление, рулетка, карта).

### 4.6. Контент и SEO
- Мета-теги, sitemap, OG-превью — базово уже есть; усилить под товары/категории.
- Подключение домена и HTTPS вместо IP.

### 4.7. Инфраструктура
- Резервное копирование БД и картинок по расписанию.
- Мониторинг (Sentry уже поддержан в конфиге — включается DSN).

## 5. Принцип внедрения без переделок

- **Новые блоки = новые компоненты** в `components/` — добавляются на страницу одной строкой.
- **Настройки — в конфигах и админке**, не в коде (`site.ts`, `categoryGroups.ts`, ShopSettings).
- **Данные — из МойСклад**: расширение каталога не требует доработки сайта.
- **Расширение модели БД — через миграции** (Alembic), без потери данных.
- **Журнал работ — `SPRINTS.md`**: история изменений и решений, чтобы подхватить работу в любой момент.

## 6. Предлагаемые этапы

1. **Сейчас:** наполнить МойСклад (описания/фото/характеристики топ-товаров), задеплоить этап 1,
   подключить домен + HTTPS.
2. **Этап 2:** фильтры каталога (цена/наличие), подборки на главной, похожие товары.
3. **Этап 3:** промо/акции из админки, автокомплит поиска, доработка мобильной версии.
4. **Далее:** аналитика, резервное копирование, сезонные баннеры, тёмная тема.

После согласования структуры заказчик предоставит примеры оформления отдельных блоков и карточек —
они внедряются поверх текущей архитектуры без переписывания.
