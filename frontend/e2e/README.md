# E2E-тесты (Playwright)

Проверяют витрину «как видит браузер»: каталог, поиск, карточку товара и **полный путь
покупки** (каталог → корзина → оформление → успех).

## Запуск

Тесты гоняются **с хоста против поднятого стека** (через nginx на `http://localhost`).

```bash
make up                      # стек должен быть запущен
cd frontend && npm install   # один раз — ставит @playwright/test
npx playwright install       # один раз — качает браузер chromium + headless shell

make test-e2e                # из корня проекта
# или из frontend/:
npm run test:e2e             # обычный прогон
npm run test:e2e:ui          # интерактивный UI-режим
npm run test:e2e:report      # открыть HTML-отчёт после прогона
```

База настраивается через `E2E_BASE_URL` (по умолчанию `http://localhost`).
Путь к docker — через `DOCKER_BIN` (по умолчанию `docker`).

## Тестовые данные (сид)

`global-setup.ts` перед прогоном засевает один товар `E2E Тестовый товар`
(`stock=10`, артикул `E2E-TEST-001`), `global-teardown.ts` — удаляет его и созданные
тестовые заказы. Оба шага идут через `docker compose exec backend python3`.

⚠️ Артикул `E2E-TEST-001` **заведомо отсутствует в МойСклад**, поэтому фоновая отправка
тестового заказа не находит товар и **не создаёт реальный заказ в МойСклад** — склад
клиента не засоряется. Если сид не выполнился (нет docker) — тест покупки помечается
как пропущенный, а не падает.

## Заметки

- Тесты идут **последовательно** (`workers: 1`): делят один стек и одну БД.
- Селекторы цепляются за роли/тексты и стабильные классы (`.pcard`, `.pdp__title`,
  `.lineitem`, `.thanks__order`) — см. spec-файлы.
